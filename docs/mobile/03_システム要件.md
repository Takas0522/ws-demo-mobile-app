# 3. システム要件

> ISO/IEC 25010:2011 ソフトウェア品質モデルに基づく機能要件・非機能要件の定義

## 3.1 機能要件

### FR-1: 認証機能

| ID     | 要件                                                                       | 優先度 |
| ------ | -------------------------------------------------------------------------- | ------ |
| FR-1.1 | 管理画面はログイン ID とパスワードによるセッションベース認証を提供する     | 必須   |
| FR-1.2 | REST API は JWT トークンによるステートレス認証を提供する                   | 必須   |
| FR-1.3 | 管理者ログイン（`admin-login`）と一般ユーザーログイン（`login`）を分離する | 必須   |
| FR-1.4 | JWT トークンのリフレッシュ機能を提供する                                   | 必須   |
| FR-1.5 | パスワード変更機能を API 経由で提供する                                    | 必須   |
| FR-1.6 | セッションタイムアウトは 30 分とする                                       | 必須   |

### FR-2: 商品管理機能

| ID     | 要件                                                              | 優先度 |
| ------ | ----------------------------------------------------------------- | ------ |
| FR-2.1 | 全商品の一覧表示機能を提供する（管理画面 / API）                  | 必須   |
| FR-2.2 | 商品の詳細情報表示機能を提供する                                  | 必須   |
| FR-2.3 | 商品情報の編集・更新機能を提供する（管理者のみ）                  | 必須   |
| FR-2.4 | 商品名によるキーワード検索機能を API で提供する                   | 必須   |
| FR-2.5 | 価格変更時に価格履歴を自動記録する                                | 必須   |
| FR-2.6 | 価格履歴の参照機能を API で提供する                               | 必須   |
| FR-2.7 | 商品更新時にバリデーション（商品名必須・単価 1 以上等）を実施する | 必須   |

### FR-3: ユーザー管理機能

| ID     | 要件                                                             | 優先度 |
| ------ | ---------------------------------------------------------------- | ------ |
| FR-3.1 | 全ユーザーの一覧表示機能を提供する（管理画面）                   | 必須   |
| FR-3.2 | ユーザー情報として ID・ログイン ID・名前・種別・作成日を表示する | 必須   |
| FR-3.3 | ユーザー一覧からフラグ管理画面への導線を提供する                 | 必須   |

### FR-4: フィーチャーフラグ管理機能

| ID     | 要件                                                          | 優先度 |
| ------ | ------------------------------------------------------------- | ------ |
| FR-4.1 | ユーザー単位でフィーチャーフラグの有効/無効を設定できる       | 必須   |
| FR-4.2 | フラグ未設定のユーザーにはデフォルト値を適用する              | 必須   |
| FR-4.3 | フラグ設定は UPSERT（存在すれば更新、なければ挿入）で処理する | 必須   |
| FR-4.4 | API 経由でユーザーのフラグ状態を取得できる                    | 必須   |

### FR-5: 購入機能

| ID     | 要件                                          | 優先度 |
| ------ | --------------------------------------------- | ------ |
| FR-5.1 | 商品の購入機能を API で提供する               | 必須   |
| FR-5.2 | 購入時の単価を購入履歴に記録する              | 必須   |
| FR-5.3 | 購入数量は 100 の正の倍数であることを検証する | 必須   |
| FR-5.4 | ユーザーの購入履歴を API で取得できる         | 必須   |

### FR-6: お気に入り機能

| ID     | 要件                                        | 優先度 |
| ------ | ------------------------------------------- | ------ |
| FR-6.1 | お気に入り一覧の取得機能を API で提供する   | 必須   |
| FR-6.2 | お気に入りの追加・削除機能を API で提供する | 必須   |
| FR-6.3 | フィーチャーフラグによる機能制御を実施する  | 必須   |
| FR-6.4 | 同一商品の重複登録を防止する                | 必須   |

### FR-7: ヘルスチェック

| ID     | 要件                                             | 優先度 |
| ------ | ------------------------------------------------ | ------ |
| FR-7.1 | 認証不要のヘルスチェックエンドポイントを提供する | 必須   |

## 3.2 非機能要件（ISO/IEC 25010 品質特性）

### NFR-1: 機能適合性（Functional Suitability）

| ID      | 要件                                               |
| ------- | -------------------------------------------------- |
| NFR-1.1 | 全ビジネスルール（BR-1 〜 BR-6）を満たすこと       |
| NFR-1.2 | データの CRUD 操作が DB の整合性制約を維持すること |

### NFR-2: 性能効率性（Performance Efficiency）

| ID      | 要件                                                         |
| ------- | ------------------------------------------------------------ |
| NFR-2.1 | 管理画面のページ表示は 3 秒以内に完了すること                |
| NFR-2.2 | REST API の応答時間は 1 秒以内であること                     |
| NFR-2.3 | SQLite データベースは WAL モードで同時アクセスに対応すること |

### NFR-3: 互換性（Compatibility）

| ID      | 要件                                                                  |
| ------- | --------------------------------------------------------------------- |
| NFR-3.1 | REST API は CORS に対応し、異なるオリジンからのアクセスを許可すること |
| NFR-3.2 | API レスポンスは JSON 形式（UTF-8）であること                         |
| NFR-3.3 | Java 7 互換のバイトコードを生成すること                               |

### NFR-4: 使用性（Usability）

| ID      | 要件                                               |
| ------- | -------------------------------------------------- |
| NFR-4.1 | 管理画面は日本語の UI を提供すること               |
| NFR-4.2 | エラー発生時は適切なエラーメッセージを表示すること |
| NFR-4.3 | ナビゲーションバーによる画面間移動を提供すること   |

### NFR-5: 信頼性（Reliability）

| ID      | 要件                                                                  |
| ------- | --------------------------------------------------------------------- |
| NFR-5.1 | 外部キー制約・UNIQUE 制約・CHECK 制約によりデータ整合性を保証すること |
| NFR-5.2 | DB トリガーにより価格履歴の記録漏れを防止すること                     |
| NFR-5.3 | 不正な入力に対してバリデーションエラーを返却すること                  |

### NFR-6: セキュリティ（Security）

| ID      | 要件                                                                                    |
| ------- | --------------------------------------------------------------------------------------- |
| NFR-6.1 | パスワードは BCrypt（strength=10）でハッシュ化して保存すること                          |
| NFR-6.2 | JWT トークンは HS256 アルゴリズムで署名し、有効期限を 24 時間とすること                 |
| NFR-6.3 | 未認証リクエストは管理画面ではログインページへリダイレクト、API では 401 を返却すること |
| NFR-6.4 | 管理者専用操作は `user_type` による権限チェックを実施すること                           |

### NFR-7: 保守性（Maintainability）

| ID      | 要件                                                                             |
| ------- | -------------------------------------------------------------------------------- |
| NFR-7.1 | レイヤードアーキテクチャ（Action → Service → DAO）を採用すること                 |
| NFR-7.2 | Spring DI によりコンポーネント間の結合度を低減すること                           |
| NFR-7.3 | Struts 設定ファイルを機能単位で分割すること（struts-admin.xml / struts-api.xml） |
| NFR-7.4 | ログ出力は SLF4J + Log4j で統一すること                                          |

### NFR-8: 移植性（Portability）

| ID      | 要件                                                      |
| ------- | --------------------------------------------------------- |
| NFR-8.1 | 組込み Tomcat により単独で起動可能であること              |
| NFR-8.2 | SQLite を使用し、外部 DBMS のインストールを不要とすること |
| NFR-8.3 | Maven によるビルド・実行が可能であること                  |
